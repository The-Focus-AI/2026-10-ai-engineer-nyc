Bootstrapping Domain Evals Without Public Benchmarks

Chapter 1 · Theme 01 thesis

The core shift across 11 talks

Public benchmarks never measure a team's real task, so builders must engineer bespoke evaluation loops—synthesizing inputs from known answers, replaying historical outages, backtesting dated web snapshots, and grading trajectories with behavior rubrics—or redesign the agent until it is evaluable.

Across enterprise RAG, legal review, creative writing, code review, accounting, and quantitative investing, speakers converged on the same wall: off-the-shelf benchmarks tell you nothing about whether your agent works, and domain experts cannot hand-grade thousands of runs. Air Canada inverted dataset creation by generating questions from known source pages and populating legal templates with clauses engineered to breach or pass rules, even re-architecting an agent purely to make it deterministically evaluable. Greptile benchmarks prompt changes against historical outage-causing PRs; Bridgewater hand-labeled 200 investment queries in a week to lift precision@10 from 60% to 95%; Exa Snapshot backtests predictive agents against 400 billion dated web pages without lookahead leakage; Towards AI runs five drafts per prompt under a two-stage cross-family rubric; and Basis grades ground-truth-free production runs with behavior specs and trajectory forking. The sharp counter-position centers on the grader itself: Sonar and Air Canada both showed that uncalibrated LLM-as-judge verdicts flip across identical runs and add noise rivaling the agent's own error rate.

Inverting the dataset: write the answer first and replay real outages

In Inside the Fable War Room (00:15:44), Ford Prior argued that benchmarking against recent production code as golden data revealed that once rich domain context is synthesized, smaller Sonnet-class models generate legacy code as well as frontier models at much lower cost. In How to build an AI code review agent: from the creators of Greptile (00:05:41), Daksh Gupta argued that because catastrophic bugs occur in roughly one in a thousand pull requests and live review output cannot prove bug absence, prompt changes must be benchmarked against a catalog of historical outage-causing PRs.

In Write the Answer First: Generating Eval Datasets for Agents With No Benchmark (00:05:31), Nathanael Weill argued that generating synthetic questions from known source pages and checking retrieval in code accelerated iteration from one experiment per week to one per business day while eliminating brittle pipeline rules. In Write the Answer First: Generating Eval Datasets for Agents With No Benchmark (00:13:36), Nathanael Weill argued that populating existing legal contract templates with synthetic clause arrays engineered to either violate or satisfy known rules creates ground-truth breach labels by construction and runs evaluations in five minutes.

Point-in-time backtesting and golden domain corpora

In A Hedge Fund as a Function (00:09:20), Frank Long argued that because real steps combine multiple runners and tune model size, thinking effort, harness, skills, and hooks, workflows must be compartmentalized into evaluable units with a clear north-star metric.

In Search the Web as It Was: An Introduction to Exa Snapshot (00:07:50), Ryan Ahern argued that testing predictive models on live web search leaks post-event outcomes, whereas querying snapshots at fixed horizons before an event evaluates what signals were genuinely discoverable without lookahead bias.

Chapter 4 · Evidence across 5 talks

Rubrics, process supervision, and firm-wide unit testing for agents

In Process Supervision for Agents That Do Long-Horizon Work (00:12:01), Mitchell Troyanovsky argued that distilling core workflow opinions into 'behavior specs' creates a ground-truth-free rubric that grades any production trajectory whenever a relevant trigger arises, scaling supervision signal far faster than static outcome evals. In Process Supervision for Agents That Do Long-Horizon Work (00:13:40), Mitchell Troyanovsky argued that when a multi-hour, thousand-call trajectory violates a behavior spec, builders can iterate on context fixes rapidly either by forking state right before the bad decision or by cheaply simulating the production prompt and skills in a coding subagent.

In Can Any Model Write Like Me? Building a Benchmark for Creative Writing (00:00:00), Louis-François Bouchard argued that aI writing slop persists as models scale not merely through overused vocabulary, repetition, and hallucination, but fundamentally because generated prose collapses into a generic, voiceless average rather than matching a specific author's tone. In Can Any Model Write Like Me? Building a Benchmark for Creative Writing (00:05:34), Louis-François Bouchard argued that generating five drafts per prompt across ten published and held-out scripts captures intra-model variance—which widens as model quality drops and masks lucky one-in-five outlier drafts—without making benchmark runs prohibitively expensive.

In Can Any Model Write Like Me? In Can Any Model Write Like Me? In Balancing Acceleration and Safety for AI Agents (00:11:58), John Feminella argued that because model upgrades act like changing runtime dependencies that can silently alter output quality, firms should provide shared self-serve evaluation infrastructure—analogous to unit testing rather than centralized sign-off queues—where teams supply only agent-specific assertions. Chapter 5 · Boundaries & debates

Where speakers pushed back and drew the boundary

No operational pattern at AI Engineer NYC went unqualified. Across the corpus, 2 counter-claims pushed back on naive versions of this shift—highlighting where judges introduce variance, where caches break, or where human judgment stays irreducible.

Counter-position · Tariq Shaukat (The Machine that Changed the World, vAI, 00:08:01): LLMs are unreliable standalone verification judges because their verdicts flip 7–17% of the time across identical runs and change 7–34% of the time when challenged with a simple 'are you sure?' prompt.
“depending on the model and the situation, between seven and seventeen percent of verdicts change across what they call identical replications.”Tariq Shaukat · The Machine that Changed the World, vAI · 00:08:01
Counter-position · Nathanael Weill (Write the Answer First: Generating Eval Datasets for Agents With No Benchmark, 00:16:18): LLM-as-judge scoring introduced variance comparable to the contract agent's own error rate, making calibrating a judge harness nearly as hard as building the underlying agent.
“Like we got so much noise compared to the noise with the with the agents that we're doing. Solving this problem is almost as hard as solving the whiteboard.”Nathanael Weill · Write the Answer First: Generating Eval Datasets for Agents With No Benchmark · 00:16:18
